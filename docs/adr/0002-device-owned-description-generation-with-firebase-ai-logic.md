# Device-Owned Description Generation with Firebase AI Logic

Save and Description Generation run as persistent Android WorkManager work rather than being awaited by the edit screen or owned by a server job. After synchronous local validation, **Save & generate description** persists the visible draft as work input, closes the edit screen immediately, and optimistically presents the submitted Item without waiting for remote persistence. The background workflow unconditionally saves every captured Item field, even when another Member changed the Item after the work was enqueued; the later Gemini result patches only the Description and update attribution. The worker calls Gemini through Firebase AI Logic's Gemini Developer API backend and sends the Item Photo as inline image data. This reuses the app's established device background-work model and Firebase stack while keeping the provider API key out of the APK, accepting that completion remains dependent on the originating installation and its authenticated Firebase session, that intervening Member changes can be lost, and that a permanent background Save failure can temporarily leave optimistic state that was never persisted remotely.
